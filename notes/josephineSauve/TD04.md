# TD04 – Nouvelle fonctionnalité : afficher les dates

Fonctionnalité : afficher la première et la dernière date d'observation pour l'instrument **et** pour le benchmark. Elle s'appuie sur les helpers du TD02. Pas de calcul de rendements.

## Code ajouté dans `src/main.py`

```python
def get_first_date(prices):
    return prices[0]["date"]

def get_last_date(prices):
    return prices[-1]["date"]
```

Intégré dans `display_market_summary`, entre `Observations` et `First close` :

```python
print(f"First date   : {get_first_date(prices)}")
print(f"Last date    : {get_last_date(prices)}")
```

Comme `display_market_summary` est réutilisée pour les deux séries, l'instrument et le benchmark affichent les dates sans dupliquer de code.

## Workflow Git

```bash
git status                                   # partir d'un working tree propre
git switch -c feature/display-observation-dates
git add src/main.py
git diff --staged
git commit -m "feat: display first and last observation dates"
git log --oneline --graph --decorate --all   # comparer les branches
git diff josephineSauve..feature/display-observation-dates
git switch josephineSauve
git merge feature/display-observation-dates  # fast-forward
git branch --merged                          # la feature est listée comme fusionnée
git branch -d feature/display-observation-dates   # après la capture 03_branch_merge.png
```

Le merge est un **fast-forward** : `josephineSauve` n'avait pas avancé depuis la création de la branche, Git a donc simplement déplacé le pointeur sur le commit de la feature. Pas de commit de merge, l'historique reste linéaire.

Un **conflit de merge** apparaît quand les deux branches modifient la même zone d'un fichier : Git ne peut pas choisir seul, il faut lire les marqueurs `<<<<<<<` / `=======` / `>>>>>>>`, choisir le contenu final, retirer les marqueurs, puis `git add` et terminer le merge.
